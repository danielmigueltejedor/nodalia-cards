# Releases

`package.json.version` is the source of truth. `src/version.ts` is generated by
`pnpm version:sync`; cards re-export it. Public generated JS embeds the same value.

1. Add concise user-facing changes under `## Unreleased` in
   `CHANGELOG-PRERELEASES.md` (previews) or `CHANGELOG.md` (stable). Include a
   `### Added`, `### Changed` or `### Fixed` section; keep technical audit detail in
   the audit document.
2. Run `pnpm release:alpha --dry-run`, `pnpm release:beta --dry-run`,
   `pnpm release:rc --dry-run` or `pnpm release --dry-run` to inspect the next version.
3. Run without `--dry-run` to update package/version references, promote the
   curated changelog section and rebuild. These commands never commit, tag,
   push or publish. A missing changelog fails before version files are changed.
4. Review the diff and `pnpm validate`. Keep YAML compatibility and inspect
   rendering if UI changed. Commit/merge the reviewed version change.
5. Tag that exact commit as `v<package.version>` and push the tag. The release
   workflow runs the same static and browser gates as CI before building,
   checking version/artifact consistency, generating hashes/SBOM, attesting
   provenance and publishing the prerelease/stable assets.
6. Verify the release is public, the prerelease flag is correct and the uploaded
   `nodalia-cards.js` hash matches `release/SHA256SUMS`.

Channel progression is alpha → beta → rc → stable. The same channel increments
its number; promotion starts at 1, stable removes the suffix, and a new preview
from stable starts the next patch. A major/minor release is an explicit product
version decision: use an explicit target, for example
`pnpm release:alpha --version=3.0.0-alpha.1 --dry-run`, review it, then run without
`--dry-run`. The target must advance the existing version and match the requested
channel; invalid targets fail before any files are changed.
Do not silently infer a major upgrade from dependency availability.

HACS continues to load only `nodalia-cards.js`. Source TS, tooling and tests are
not runtime npm dependencies. Published tags/releases are immutable historical
checkpoints; do not rerun an old release expecting the new workflow to apply.

Stable promotion retires the active preview in the roadmap. Both stable and preview
GitHub releases use their curated changelog sections; missing notes block publication.
