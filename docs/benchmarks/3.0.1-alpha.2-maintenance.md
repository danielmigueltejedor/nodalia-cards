## Summary

- **Advanced Vacuum map frames:** 20 new frames take **60–64% less synchronous work** (Chromium 56.5 → 20.6 ms, WebKit 55 → 21 ms, iPhone WebKit 55 → 22 ms). Map child-list changes and removed nodes drop to zero (from 60/120).
- **Advanced Vacuum robot updates:** 120 robot updates complete **17–34% sooner** (total median 178 → 147 ms, 214 → 142 ms, 211 → 141 ms) and no longer mutate the map (840 attribute changes and 840 removed nodes → 0).
- **Lock:** relevant updates cost more synchronous work (+60–92%, about 6–7 ms per 120 updates, ≈0.06 ms per update) for the coordinated state transitions; mount gains about 1 ms for the entrance. Lock no longer replaces its content: removed nodes fall from 480 to 0 per 120 updates.
- **Advanced Vacuum relevant updates:** +14–25% synchronous work but 16–20% lower total time, because unchanged map layers are kept.
- **Humidifier and Weather:** changes are within run-to-run variation.
- **Desktop WebKit Advanced Vacuum lifecycle (100 cycles):** median 107 → 177 ms, but the samples are bimodal in both versions (alpha.2: 108–114 ms in three rounds, 177–228 ms in four; 3.0.0 also reaches 135–177 ms). Chromium (−2.6%) and iPhone WebKit (−8.0%) do not show it. Treat it as inconclusive, not as a measured regression. Chromium lifecycle leaves zero residual nodes in both versions; used heap after cleanup is about 6.5 KB higher and constant across rounds.

The 3.0.1 fixes for Masonry/Sidebar/Panel relayout loops (#321), Safari scroll anchoring (#320) and ignored taps after a slider are behavioural and are not part of this timing fixture. Browser regressions cover them (`view-layout-feedback`, `interaction-scroll-stability`, `slider-tap-suppression`): for example 15 whole-view rebuilds per 1.5 s → 0 in the Masonry fixture, and a 122 px scroll jump → 0 in iPhone WebKit.
