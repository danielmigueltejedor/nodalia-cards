### Where the gain comes from

- Cards no longer read `shadowRoot.innerHTML` to learn whether they rendered. That serialized the whole tree on every HA state change, related or not. Unrelated updates are where it shows: on Chromium, 120 of them cost Climate 9.2 → 0.6 ms, Graph 5.3 → 1.4 ms, Light 4.2 → 1.5 ms, Fan 2.7 → 0.6 ms and Cover 3.1 → 0.5 ms. Cards that already skipped most of this work (Calendar, Navigation, Lock) are unchanged.
- Advanced Vacuum and Vacuum discover their helper entities once per entity catalog (ids, friendly names, registry identity) instead of scanning on each update.
- `normalizeTextKey`, number and date formatting are memoized or use shared locale formatters.
- The parent width used by the compact layout is measured only when it decides the layout.

### Negative or neutral results

- **Mount** is not faster. The sum over 25 cards moves by a few milliseconds the wrong way (+1.8% Chromium, +5.0% and +6.2% on the WebKit engines, whose timings are whole milliseconds) and the per-card median change is 0.0%. The likely cause is that a cold mount fills the new text-key and formatter caches with strings it has not seen yet; it is not a claimed cost or a measured one.
- **Advanced Vacuum robot switch** (one `setConfig` plus one assignment on a 1,700-entity catalog) costs a few milliseconds more on WebKit: the catalog stamp compares 1,700 entries twice where the old code scanned once. It is a one-off operation, and every later update is cheaper.
- Differences near the timer resolution are not speed claims; check the p95 columns before reading anything into a single small row.
