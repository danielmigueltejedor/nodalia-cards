An isolated sequence of Graph histories (100/1,000/5,000/10,000) reproduces a pending tooltip frame at the next preparation, while a fresh page completes the same operations. These failures must not become zero-cost wins or missing rows hidden in release notes.
- The old harness also allowed saved state/module work from preceding profiles to affect later profiles. Automatic helper discovery reached 5,566 catalog enumerations per 120 assignments in the sequential run, but only 240 in an isolated page. This is a fixture-boundary issue, not proof that every HA update costs the sequential figure. The permanent runner now creates a fresh page/import for each profile outside timed dispatch and clears fixture storage before preparation. Warm reconnect/cached artwork are explicitly warmed within their own profile.
- The preserved results predate this isolation correction and the latest runtime fixes. They cannot certify performance of the candidate, RC or stable.
- 147 explicit skips cover generation-2 unsupported gestures/API v3, with no fake performance delta. Other unavailable metric seams remain null. No browsers are averaged.

## Interpretation and corrections

Published beta rewrites 480 Media / 483 embedded Summary mutation records per 120 unrelated HA assignments. The operation count is reproducible in every available engine; standalone/embedded regressions fail against the original source and pass with zero records after value comparisons and Summary signature initialization. A source candidate is not a published release, so no official post-fix percentage is claimed.

The isolated helper regression fails at 240 scans before and passes at 120 after sharing discovery within a synchronous HA assignment. Availability and mutable registry discovery still refresh between assignments; no HA object survives the lookup scope. The separate seven-round [candidate diagnostic](../audits/rc-evidence/helper-before-after.json) preserves raw samples/hashes and is explicitly not official release evidence. It must not be compared directly with the sequential 5,566-scan workload.

Several mounts/remounts have roughly 50 ms more settle time in beta, while synchronous cost is much smaller. The locale reconciliation/quiet-period boundary is an elapsed-time cost; it is not a claim that dispatch CPU doubled. State signatures, availability validation and ownership add correctness work to relevant Camera/Calendar/Scenes/Cover/Graph updates. Absolute dispatch differences are generally fractions of a millisecond per assignment, rather than the whole 120-assignment batch. Their user-facing impact and candidate deltas still require an isolated four-engine reference run; no blind >5% acceptance is applied.

Media 250 updates illustrates why work/settle are separate: Chromium dispatch improves but total elapsed time worsens in this capture. Neither result is hidden. Startup, Graph data and explicit helper paths also have measured improvements; none supports a global speed claim.

## Vacuum correctness and scope

All 200-move beta pointer/simulated-touch samples in the three available engines preserve image/marker identity, deliver 50 consumed robot + map updates, change scale, and have zero full renders/overlay rebuilds during gesture. The shorter profiles deliver five/twenty updates. The archived touch profile used a synthetic event with the TouchEvent prototype; it is not native-constructor evidence. The permanent harness now uses brand-checked native objects. Generation 2 does not exercise these gestures successfully here, so this is beta-only correctness/performance data, not a speed comparison against generation 2. iPhone WebKit is emulation, not physical Safari FPS.
